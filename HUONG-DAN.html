📘 Hướng dẫn cài đặt & sử dụng
OCR PDF → Word (Gemini / OpenAI · Pandoc · MathType · Supabase)

Web app chuyển file PDF (đề thi, tài liệu Toán–Lý chứa công thức, bảng biểu, hình vẽ) thành file Word .docx giữ nguyên công thức toán. Bạn đang mở file HUONG-DAN.html nằm trong source code — làm theo lần lượt từ mục 1 đến mục 10 là có bản deploy hoàn chỉnh.

Next.js 15 + React 19 Gemini API hoặc OpenAI-compatible Xuất OMML (Pandoc) hoặc MathType OLE Lưu file trên Supabase 3 ngày Deploy miễn phí trên Vercel

↑1Giới thiệu & cách hoạt động

Ứng dụng gồm 2 nửa:

  • Chuẩn bị task (trong trình duyệt): render từng trang PDF thành ảnh rồi upload lên Supabase, đồng thời tạo task kèm API key của bạn.
  • OCR chạy trên server (dạng task nền): server đọc các trang đã upload, gọi Gemini/OpenAI từng trang một. Khuyến nghị bật worker Render (mục 4.4) — OCR chạy liền mạch, tự chờ qua rate-limit, không phụ thuộc giới hạn 60s. Bạn có thể đóng tab hoàn toàn sau khi upload xong — quay lại là thấy tiến độ/kết quả.
Key API của bạn an toàn thế nào khi chạy trên server? Key được đưa vào state của job (bucket ocr-jobs riêng tư, chỉ service-role đọc được) chỉ trong lúc job chạy — bị xoá ngay lập tức khi job xong / lỗi / huỷ. Cron hằng ngày còn quét dọn key của job treo quá 2 giờ và xoá toàn bộ job cũ sau 3 ngày. Key không bao giờ được trả về trình duyệt trong các API trạng thái.

Luồng xử lý một file PDF:

  1. Bạn kéo-thả PDF (một hoặc nhiều file) → app render + upload các trang, tạo task.
  2. Server OCR từng nhóm trang, tự nối bước, tự rotate key khi bị giới hạn, Gemini tự lùi model 3.7 → 3.6 → 3.5 khi hết hạn mức.
  3. Bạn đi làm việc khác. Tab còn mở: có âm thanh + thông báo desktop khi xong. Tab đã đóng: mở lại app là thấy task “Xong ✓”.
  4. Bấm Mở kết quả → Markdown + hình được cắt từ các trang đã render, xem trước bằng KaTeX, sửa nếu muốn.
  5. Bấm xuất Word → chọn Equation (OMML) (máy chủ Pandoc tích hợp) hoặc MathType (OLE) → file tải về máy và lưu trên server 3 ngày.
Nhiều API key, tự xoay vòng: dán nhiều key (mỗi dòng một key). Khi một key bị giới hạn tốc độ (429/quota), app tự chuyển sang key kế tiếp và làm lại — bạn không phải bấm lại gì cả. Hết sạch key ở model đang dùng, app còn tự hạ model Gemini (3.7 → 3.6 → 3.5) rồi thử lại với nguyên các key đó.

↑3Thiết lập Supabase (15 phút)

3.1. Tạo project

  1. Vào supabase.com/dashboard → New project.
  2. Đặt tên bất kỳ (ví dụ ocr-word), tạo mật khẩu database (không cần nhớ), chọn region gần bạn nhất (Singapore) → Create new project.
  3. Chờ 1–3 phút cho project khởi tạo xong.

3.2. Tạo 2 bucket lưu trữ (chạy script SQL có sẵn)

  1. Menu trái → SQL Editor → New query.
  2. Mở file supabase/setup.sql trong source code, copy toàn bộ nội dung, dán vào ô query → Run (Ctrl+Enter).
  3. Kết quả (“Success. No rows returned” là đúng). Script đã tạo 2 bucket private là temp-images và word-exports + khoá toàn bộ truy cập từ ngoài (RLS deny-all) — chỉ server của bạn với key service_role mới đọc/ghi được.
  4. Chạy lại script nhiều lần cũng không sao (an toàn, có on conflict do nothing).
Kiểm tra nhanh: vào Storage trên menu trái, phải thấy 3 bucket temp-images, word-exports và ocr-jobs, biểu tượng có dấu khoá (Private). Nếu thiếu (ví dụ bản cũ chỉ có 2), chạy lại script — an toàn, không mất dữ liệu cũ.

3.3. Lấy 2 thông tin cần thiết

  1. Menu trái → Project Settings (⚙️) → API.
  2. Copy Project URL — dạng https://xxxxx.supabase.co. Đây là SUPABASE_URL.
  3. Kéo xuống Project API keys → dòng service_role → bấm Reveal → copy. Đây là SUPABASE_SERVICE_ROLE_KEY.
Bảo mật: chỉ dùng key service_role ở môi trường server (Vercel / file .env.local). Tuyệt đối không đưa key này vào code, không commit lên GitHub, không dán vào bất kỳ đâu công khai. App được thiết kế để key này chỉ tồn tại trong biến môi trường server.

↑4Deploy lên Vercel (10 phút)

4.1. Đưa source lên GitHub

Nếu source đã ở trên GitHub của bạn thì bỏ qua. Nếu chưa, có 2 cách:

Cách nhanh (không cần cài gì): nút Code trên repo → Download ZIP → giải nén → tạo repo mới trên GitHub → uploading an existing file → kéo toàn bộ file vào (nhớ bỏ qua thư mục node_modules và .next nếu có) → Commit changes.

Cách chuẩn (dòng lệnh):

git clone <url-source-cua-ban>
cd ten-thu-muc
git remote set-url origin https://github.com/<ban>/<repo-moi>.git
git push -u origin main

4.2. Import vào Vercel

  1. Vào vercel.com/dashboard → Add New… → Project.
  2. Chọn repo vừa push → Import. Vercel tự nhận Next.js, giữ nguyên mọi thiết lập mặc định.
  3. Mở rộng Environment Variables, thêm từng dòng sau (name → value):
SUPABASE_URL = https://xxxxx.supabase.co          ← Project URL ở mục 3.3
SUPABASE_SERVICE_ROLE_KEY = eyJhbGciOi...         ← service_role key ở mục 3.3
CRON_SECRET = dat-chuoi-ngau-nhien-bat-ky         ← tự nghĩ một chuỗi dài 16+ ký tự
PANDOC_URL = https://pandoc-server.onrender.com/convert      (tuỳ chọn, đã có mặc định)
MATHTYPE_URL = https://latex2mathtypeweb.onrender.com        (tuỳ chọn, đã có mặc định)
CRON_SECRET là gì? Mật khẩu bảo vệ endpoint dọn dẹp file cũ. Vercel sẽ tự động gửi nó theo dạng Authorization: Bearer <CRON_SECRET> mỗi ngày lúc 03:00 UTC để xoá file quá 3 ngày. Chỉ cần là một chuỗi ký tự ngẫu nhiên, không cần nhớ.
  1. Bấm Deploy → chờ ~1 phút.
  2. Khi xong, Vercel đưa bạn một link dạng https://ten-project.vercel.app — đây chính là app của bạn.

4.3. Kiểm tra sau khi deploy

Rất quan trọng — dùng đúng domain: luôn dùng domain production (xem Vercel → Project → Settings → Domains, ví dụ https://<tên-project>.vercel.app). Đừng bookmark URL dạng ...-dfn1azhx8-....vercel.app (URL của từng lần deploy): nó đổi sau mỗi lần deploy và bị Vercel khoá SSO — trang bạn xem được nhưng call nội bộ của server bị 401, task sẽ không bao giờ chạy.
  • Mở link → thấy giao diện app (khung cấu hình bên trái, vùng thả PDF bên phải).
  • Vercel → Project → Settings → Cron Jobs → thấy cron /api/cleanup lịch 0 3 * * * (giờ UTC).
  • OCR thử + xuất thử 1 file (mục 6) → status hiện link ...supabase.co/storage/v1/object/sign/word-exports/... là Supabase đã nối đúng.

4.4. (Khuyến nghị) Worker OCR trên Render — OCR liền mạch, không giới hạn 60s

Theo mặc định, OCR chạy bằng chuỗi function của Vercel (mỗi bước ≤ 60s) — với tài liệu dày đặc, một bước có thể bị cắt giữa chừng khiến task gián đoạn. Worker trên Render chạy trọn vẹn cả task trong một tiến trình: OCR từng trang liên tục, bị rate-limit thì tự chờ ~45s rồi thử lại thay vì fail, model lỗi tự lùi 3.7 → 3.6 → 3.5. Cài một lần duy nhất, sau đó app tự dùng worker khi thấy 2 biến môi trường bên dưới.

  1. Vào dashboard.render.com → đăng nhập bằng GitHub → New + → Web Service → Build and deploy from a Git repository → kết nối GitHub → chọn repo của app.
  2. Điền cấu hình:
    MụcGiá trị
    Project Nameocr-worker (tuỳ ý)
    Language / RuntimeNode
    Branchmain
    RegionSingapore
    Root Directoryworker ← quan trọng, đừng để trống!
    Build Commandnpm install
    Start Commandnode server.mjs (hoặc npm start)
    Instance TypeFree
  3. Kéo xuống Advanced → Add Environment Variable, thêm 3 biến: 
    SUPABASE_URL = https://<project-ref>.supabase.co        ← giống hệt giá trị ở Vercel (mục 4.2)
SUPABASE_SERVICE_ROLE_KEY = eyJhbGciOi...               ← giống hệt giá trị ở Vercel
WORKER_TOKEN = mot-chuoi-ngau-nhien-bat-ky              ← tự nghĩ, dài 16+ ký tự
  4. Create Web Service → chờ 1–2 phút build.
  5. Kiểm tra: mở https://<tên-worker>.onrender.com/health → thấy {"ok":true,"active":0,...} là worker sống.
  6. Về Vercel → Settings → Environment Variables, thêm 2 biến: 
    OCR_WORKER_URL = https://<tên-worker>.onrender.com
OCR_WORKER_TOKEN = <giống hệt WORKER_TOKEN ở Render>
    rồi Deployments → Redeploy.
Không set 2 biến này thì app tự quay lại chạy bằng chuỗi function Vercel — mọi thứ vẫn hoạt động, chỉ là dễ gián đoạn hơn. Render free sau ~15 phút không ai dùng sẽ “ngủ”: task đầu tiên sau khi ngủ chờ thêm ~1 phút để worker thức (app tự đánh thức, task chỉ hơi chậm hơn thường lệ). Khi có job chạy, worker tự giữ tỉnh. WORKER_TOKEN bắt buộc — không ai gọi /run trái phép được.

4.5. Cập nhật app lên bản mới mà không phải redo

Mọi thứ bạn đã làm một lần (Supabase + buckets + env + worker trên Render) giữ nguyên vĩnh viễn. Các lần cập nhật sau chỉ gồm:

Thay đổi gìBạn cần làm gì
Sửa code (thư mục src/)Không phải làm gì — git push (hoặc tôi push giúp) là Vercel tự deploy lại.
File supabase/setup.sql có thay đổiChạy lại script trong Supabase SQL Editor — an toàn, chỉ thêm bucket/policy còn thiếu, không mất dữ liệu cũ. Thông báo màu vàng dạng “Bỏ qua policy…” là bình thường, không phải lỗi.
Thư mục worker/ có thay đổiRender tự deploy lại khi repo đổi (mặc định Auto-Deploy có sẵn). Nếu muốn chủ động: Render → service → Manual Deploy → Deploy latest commit.
Hướng dẫn của bản mới nói “thêm biến môi trường X”Vercel (và Render nếu biến đó của worker) → thêm → Redeploy.

Tóm lại: lần đầu cài (mục 3 + 4 + 4.4) là việc một lần; từ bản thứ hai trở đi bạn gần như chỉ cần git push.

5.0. Chạy local bằng MỘT lệnh — không cần Supabase, không cần .env (khuyên dùng)

Lệnh này khởi động app + worker OCR + Supabase giả lập (dữ liệu trong RAM) cùng lúc — chỉ cần API key Gemini/OpenAI thật là test được toàn bộ luồng: thả PDF → OCR nền → mở kết quả → xuất Word:

Rồi mở http://localhost:3943 — dán key, thả PDF, dùng như bản deploy. Muốn tắt: Ctrl+C.

6.1. Nhìn tổng quan màn hình

Cấu hình (cột trái) — mọi thiết lập lưu tự động vào trình duyệt, lần sau vào lại không phải nhập lại.
Gemini APIOpenAI Completions
↓ Khung nhập key (một key mỗi dòng) · Model · Số trang tối đa · Độ phân giải render · Hướng dẫn thêm · Tên file xuất
Tài liệu (cột phải): vùng kéo-thả PDF → nút Chạy OCR → thanh số liệu (kí tự · trang · công thức · ảnh) → dòng trạng thái → 2 nút Xuất Word → khung sửa Markdown + xem trước song song.

6.2. Cấu hình lần đầu

  1. Chọn nhà cung cấp AI:
    • Gemini API (khuyến nghị): chỉ cần key AIza.... App gửi cả file PDF trong một request — nhanh và chính xác với tài liệu nhiều trang. Giới hạn: PDF ≤ 14MB.
    • OpenAI Completions: cần Base URL (ví dụ https://api.openai.com/v1 hoặc base URL của nhà cung cấp khác), Model (ví dụ gpt-4o), và nếu muốn — số Max tokens. App render từng trang PDF thành ảnh rồi gửi theo nhóm 4 trang/request, phù hợp PDF lớn.
  2. Dán API key vào khung key: mỗi key một dòng, có thể dán nhiều key để tự xoay vòng khi gặp giới hạn tốc độ. Dòng trống bị bỏ qua.
  3. Chọn model Gemini khởi đầu: gemini-3.7-flash (mới nhất, mặc định) · gemini-3.6-flash · gemini-3.5-flash. Tự lùi model khi hết hạn mức: nếu tất cả key đều bị giới hạn ở model đang dùng, app tự thử lại với model cũ hơn — 3.7 → 3.6 → 3.5 — dùng lại nguyên các key đó (hạn mức Gemini tính riêng theo model nên key vừa bị chặn ở model cũ vẫn chạy được model kế).
  4. Số trang tối đa: mặc định 30, tối đa 200. Trang vượt số này sẽ không được OCR.
  5. Độ phân giải render: 2x phù hợp đa số; 3x cho tài liệu chữ nhỏ/nhiều chi tiết (nặng bộ nhớ hơn).
  6. Hướng dẫn thêm (tuỳ chọn): ví dụ “Giữ nguyên tên riêng trong ngoặc vuông” — được chèn thêm vào yêu cầu gửi cho model.
  7. Tên file xuất: phần tên của file Word, không dấu. Mặc định tai_lieu_ocr → file ra là tai_lieu_ocr_equation.docx hoặc tai_lieu_ocr_mathtype.docx.

6.3. Chạy OCR dạng task nền

  1. Kéo file PDF vào vùng thả (một hoặc nhiều file cùng lúc). Mỗi file trở thành một task trong danh sách.
  2. Chờ app render + upload các trang: dòng task hiện “⏫ tên-file — đang render + upload…”, dòng trạng thái đếm từng trang. Upload xong → task chuyển sang Đang chờ / Đang chạy — từ đây bạn có thể đóng tab, server tự chạy tiếp.
  3. Server OCR từng trang một, nối tiếp nhau (task hiện “Đang chạy · nhóm 3/30 · cập nhật 12s trước — Đang OCR trang 3…”). Bị giới hạn tốc độ → tự chuyển key; hết hạn mức ở model đang dùng → Gemini tự lùi 3.7 → 3.6 → 3.5.
  4. Khi task Xong ✓: bấm Mở kết quả → khung trái là Markdown thô (sửa trực tiếp), khung phải là xem trước KaTeX với hình đã cắt. Thanh số liệu cho biết tổng kí tự / trang / công thức / ảnh.
Đi làm việc khác trong lúc OCR: tab còn mở (kể cả thu nhỏ/chuyển tab khác) → khi task xong bạn nghe tiếng “ting” và nhận thông báo desktop; tiêu đề tab hiện số task đang chạy. Tab đã đóng hoàn toàn → mở lại app, danh sách task vẫn đó với đúng tiến độ (server tự nối bước, tự “hồi sinh” task đứt kết nối). Lưu ý: giai đoạn render + upload (vài chục giây đến vài phút tuỳ số trang) vẫn cần tab mở.
Kiểu chữ trong Markdown: [[IMAGE:...]] màu nhạt là marker hình chưa cắt được (trang vượt số trang tối đa hoặc toạ độ sai) — chúng sẽ bị bỏ qua khi xuất Word. Bài toán/quảng cáo dư thừa bạn có thể xoá trực tiếp trong khung Markdown trước khi xuất.

↑7Xuất Word & cơ chế lưu 3 ngày

  • File Word lưu ở đâu? Trong bucket word-exports trên Supabase của bạn, theo cấu trúc j-<mã-ngẫu-nhiên>/tên-file.docx.
  • Link tải có hạn không? Có — 3 ngày (signed URL). Sau 3 ngày link hết hiệu lực.
  • File bị xoá khi nào? Cron trên Vercel chạy lúc 03:00 UTC mỗi ngày, tự xoá mọi file (và ảnh tạm trong temp-images) có tuổi trên 3 ngày. Bạn không phải làm gì.
  • Coi lại file cũ? Vào Supabase → Storage → word-exports, chọn file → Download hoặc tạo signed URL mới.
  • Chạy dọn dẹp thủ công (ví dụ muốn xoá ngay toàn bộ file cũ):
curl -X POST https://ten-project.vercel.app/api/cleanup \
  -H "Authorization: Bearer <CRON_SECRET-cua-ban>"
# → {"removed": <số-file-đã-xoá>}
Ảnh tạm: ảnh cắt để nhúng vào Word chỉ đi kèm trong request convert và sống trong bucket temp-images trong 3 ngày, sau đó cron dọn. Không ảnh nào bị công khai — mọi bucket đều private.

Bảo mật — những gì app đảm bảo

  • Key API trên server chỉ mang tính tạm thời: key nằm trong state của job (bucket ocr-jobs private, chỉ service-role đọc được) trong lúc job chạy, và bị xoá ngay khi job xong / lỗi / huỷ. Cron hằng ngày quét xoá key của job treo quá 2 giờ và xoá toàn bộ job cũ sau 3 ngày. Các API trạng thái không bao giờ trả key về trình duyệt.
  • Chỉ có server gọi Gemini/OpenAI (từ bản task nền) — key không được nhúng vào bundle JavaScript.
  • service_role key chỉ tồn tại trên server (biến môi trường) — đã kiểm chứng không xuất hiện trong bundle JavaScript gửi xuống trình duyệt.
  • Bucket Supabase private + RLS khoá toàn bộ — ngoài server không ai truy cập trực tiếp được; tải file chỉ qua signed URL sống tối đa 3 ngày.
  • Cron endpoint yêu cầu secret — không ai gọi tay xoá dữ liệu của bạn được.
  • Preview chống XSS — mọi nội dung Markdown (kể cả do model trả về) đều được escape HTML trước khi render; URL ảnh được escape để chèn attribute.
Giới hạn đã biết: các API /api/jobs* không yêu cầu đăng nhập (thiết kế cho công cụ cá nhân/công khai) — người lạ biết URL có thể tạo job/upload vào bucket của bạn và chiếm dụng dung lượng Supabase. Nếu chia sẻ công khai, hãy theo dõi dung lượng Supabase, hoặc tự thêm bước xác thực (ví dụ mật khẩu truy cập đơn giản) trước khi mở rộng.
